# 使用与网络范围

## 首次使用

以下操作适用于 V1.0.0 构建 25 的 Apple Silicon 与 Intel 安装包。两种架构的验证范围见[发行说明](../release-notes.md)。

1. 首次安装为空白配置，请导入自己的本地 YAML 或订阅。来源不可信的配置应先查看节点、规则与外部资源。
2. 点击左侧「系统代理」的小开关即可开启代理。点击卡片文字会打开详细设置。Relay 会启动已选订阅。尚未选用订阅时，会使用列表中第一份完整配置。
3. 系统代理开启后，遵循 macOS 代理设置的应用即可联网。首次安装配套组件时，macOS 可能要求管理员授权。
4. 使用 Claude / Codex 工作流前，核对专用节点、监听器与客户端配置。配置写入前保留备份，失败后用对应恢复入口收尾。

首次打开 Relay 或首次导入配置时，系统代理保持关闭。首次点击「系统代理」即可连接，也可以先在订阅管理中指定配置。再次打开 Relay 时，会恢复上次使用的订阅、该订阅中仍存在的节点，以及上次的系统代理开关。若其他软件已接管系统代理，Relay 会保留当前网络设置。

在「代理组」选中配置或节点即可应用；组标题上的测速按钮只测该组。TUN 正在运行时切换配置，会交接内核并恢复 TUN，期间可能短暂重连。

## 开机自启动

点击左上角齿轮，在「设置」首页打开「开机自启动」。下次登录当前 macOS 用户账户时会自动打开 Relay。关闭开关即可取消后续登录启动。若 macOS 要求批准，可在「系统设置 → 通用 → 登录项」中允许 Relay。

## 普通代理与专用代理

普通端口提供 HTTP、SOCKS、混合和 Redir 设置，详见[监听端口说明](Ordinary-Proxy-Ports.md)。保存后的端口在下一次核心启动生效，当前实际监听单独显示。

普通代理遵循所选配置的分流规则。专用代理绑定明确节点，可为客户端提供独立 HTTP / SOCKS 入口。HTTP 与 SOCKS 是不同协议，请按界面显示匹配；不能把 HTTP 监听端口直接当作 SOCKS 使用。

本地启动计划会保存供下次启动使用。保存计划不代表当前运行内核已经重新加载；应核对实际运行端口与归属。

## Claude Code 与浏览器

配置应用会检查当前 Relay 专用 HTTP 入口。已有终端会话不一定重新加载配置，更新后需要重新启动相应客户端会话。浏览器入口检查当前 Relay 归属；无有效绑定时拒绝启动，不静默改用其他软件的配置。

专用浏览器使用独立用户目录。企业浏览器策略可能覆盖命令行代理设置，此时应按界面错误处理，不能把独立用户目录理解为可以绕过系统策略。

桌面登录直接使用本机 Microsoft Edge，不再以 RelayBrowser/Chrome 作为临时默认入口。Edge 固定策略使用 SOCKS 17890；开始前必须确认该端口属于 Relay 的固定节点专用监听，并确认 Edge 已退出、强制策略匹配。还需启用专用 HTTP 供 Relay 验证运行归属。

Edge 策略作用于当前用户全部 Edge 资料，使用未登录微软账号的专用资料。登录会临时变更系统 HTTP / HTTPS 默认浏览器，完成或取消时走恢复流程。旧 RelayBrowser 登录恢复记录仍可处理，不要求 Edge 或代理在线。若有未完成的恢复记录，先处理该记录。不要把临时默认浏览器变化理解为全系统流量已受保护。

## 与其他代理软件交替使用

- 两个软件可以同时打开，但本地监听端口必须避开冲突。
- 系统代理和 TUN 路由由系统共享，建议同一时间只由一个软件管理。
- Relay 的 CLI 专用浏览器使用 Relay 核对过的 HTTP 入口；桌面 Edge 登录核对专用 SOCKS17890。两软件交替使用可共享同一份 Edge 策略，但须由当前软件实际提供该专用端口。
- Claude / Codex 的用户级设置不能同时表示两个不同软件的当前选择；交替使用时需应用对应配置或恢复备份。
- 停用 Relay 接管时，用其恢复功能恢复原设置，随后核对其他软件状态。

## 能力边界

本版没有系统级按进程防直连保护，不保证覆盖任意终端、任意 Node 进程或主动忽略代理的客户端。源代码中保留的系统扩展实验模块不等于本发行版已启用。TUN、系统代理、专用监听器属于不同能力，以实际启用状态为准。

应用采用 ad-hoc 签名，安装包未签名，未经 Apple 公证。登录自启、首次启用系统代理和 TUN 切换的 Apple Silicon 实测记录来自构建 24。构建 25 专项验证了系统代理端口显示和两个 HTTP 入口。Intel 原生运行仍待验证。

## TUN

统一安装包包含 TUN 组件，安装时绑定当前登录用户。开启系统代理后仍可开启 TUN，原有本地监听端口继续提供服务。切换会短暂重启 Relay 自己的内核，已有连接可能重连。TUN 运行时可在「代理组」查看并切换节点。若 macOS 正在回收有过连接的端口，关闭 TUN 时会等待端口可用，然后自动恢复普通代理。在此期间可以保持系统代理开启。关闭 TUN 后，普通代理恢复上次的端口和最新的节点选择；自动组会保留手动固定或自动选择的状态。

## 卸载

将安装后的 `/Applications/Relay.app` 拖入废纸篓即可触发独立的自动卸载组件，不需要再运行卸载脚本。它会恢复 Relay 管理的配置，停止并移除自有组件，删除专属数据、缓存、登录项及凭据。请在卸载前导出需要保留的配置。外部修改或无法确认的状态会保留恢复记录，不会以强删来假装完成。
