# Relay AI 网络配置交接

此文件是随 App 提供的通用说明，不包含个人订阅、凭据、节点地址或电脑状态。实时配置与监听端口应以 Relay 当前读取结果为准。

## Claude Code 与专用浏览器

1. 导入你有权使用的配置，在本地代理中选择节点并准备专用 HTTP/SOCKS 监听器。
2. 在 Claude Code 配置页面读取当前状态；应用配置时，Relay 会校验监听器属于本次运行的内核，并保存恢复记录。
3. 既有终端进程需重新启动后才能读取新环境配置。Claude Code 的浏览器入口使用随 App 提供的 RelayBrowser，连接 Relay 当前专用监听器；所有者、进程或端口不匹配时会拒绝继续。
4. Claude Code 的专用浏览器仍使用独立 Chrome 配置目录。桌面登录改为直接使用已安装的 Microsoft Edge，临时作为 HTTP/HTTPS 默认应用，完成或取消后依据恢复记录恢复原处理器。
5. Edge 沿用固定 SOCKS 127.0.0.1:17890 的强制策略。Relay 开始登录前核对专用 HTTP 与 SOCKS 17890 均归当前 Relay 固定节点实例所有，并核对 Edge 已完全退出、强制策略匹配且没有已知覆盖。普通 SOCKS、其他软件占用端口或仅保存未运行的计划不能通过检查。
6. 与 Clash Party 交替使用时，两个程序不得同时占用17890。此变更不会自动迁移当前端口。Edge 策略作用于当前用户全部 Edge 资料；使用未登录微软账号的专用资料。登录完成恢复默认浏览器，不自动关闭 Edge。

## 保护范围

本版本使用代理路由与客户端配置。流量需要进入 Relay 监听器才会受该路由约束；不提供所有进程的系统级禁止直连保证，也不把普通 Node 进程统一拦截。`NO_PROXY` 等明确绕过项仍需结合实际用途核对。

如在多个代理软件间切换，请分别核对客户端配置、专用浏览器入口与端口。客户端配置文件只有一份，不会因两个软件同时打开而自动各自生效。不要让两个程序占用相同地址与端口，也不要同时启用相互竞争的系统代理或 TUN。

## 恢复

在修改配置之前保留可用的恢复记录。使用 Relay 对应模块的恢复操作，并核对系统代理、默认浏览器及客户端配置是否回到预期状态。不要把“进程正在运行”“节点测速成功”当作“所有 Claude/Codex 流量已受到系统防直连保护”。
