# Relay local geodata v1 — fixed Mihomo extension

Base: MetaCubeX/mihomo `3f27ef39f8c96bbfbc8b0b9bb10f5c9ef60149d8`, GPL-3.0. This directory holds a reviewable overlay and reproducible patch, not installed or pinned Core bytes. The current combined production extension is `relay-geodata-v1p1-3f27`, including the provider serialization supplement. See [corresponding source](../SOURCE.md) and [public build instructions](../../docs/BUILD.md). Older private integration commands below remain development-only; they are not the public release build entry point.

## Fixed contract (main/Native private)

One endpoint: `POST /relay/geodata/v1`, admitted only when the server's actual `LocalAddrContextKey` is a Unix listener. Headers cannot assert this authority. No TCP listener, URL, arbitrary path, PID, credential or caller-supplied resource filename is accepted. Normal controller authentication still applies. Kinds are exactly `geosite-dat`, `geoip-dat`, `country-mmdb`, `asn-mmdb`.

All JSON uses strict duplicate-key/unknown-field/type/UTF-8 checks and a 4 KiB request budget. Bodies:

- State: `{version:1, action:"state"}`.
- Prepare: `{version:1, action:"prepare", kind, oldSHA256, newSHA256, expectedGenerationSHA256, blobId, selector}`. `blobId` is a canonical UUID. An optional private `leaseMS` is an integer 1000..120000; default 30000. The selector is the trusted existing resource descriptor (UTF-8 up to 256 bytes, trimmed, no controls/comma), never fixed CN/RELAY. DAT validation reuses standard LoadSiteByBytes/LoadIPByBytes with the existing selector base; Main’s existing actual resource checker remains responsible for complete rule/attribute semantics. MMDB verification is structural/lookup-type validation; the selector stays part of the private selection scope. Human confirmation is completed before prepare. One monotonic deadline starts before prepare I/O and is never renewed by commit. Native uses the minimum remaining local/Core budget.
- Commit/cancel: `{version:1, action:"commit"|"cancel", nonce}`. The random 32-byte hexadecimal nonce is private and can admit at most one commit.

State returns `{version:1, capability:"local-geodata-v1", bootId, sequence, generationSHA256, resources}`. `bootId` is a process-lifetime UUID established by its first complete verified state; sequence begins at zero. Resources contains only existing verified fixed files, with unique `{kind, sha256, bytes, active}` rows. A missing kind is absent, never an all-zero digest. This first production unit only replaces existing kinds: no implicit creation/adoption. Eligibility is a stable bound-file capability: an existing GeoSite/ASN file is eligible; an existing GeoIP DAT requires loaded geodata-mode=true, Country requires false. It does not use lazy lookup/cache counters. Native must still require its verified initial-bundle binding; an HTTP row cannot adopt a new file. Incompatible kinds are unsupported. No configuration SHA is claimed: rereading `C.Path.Config()` cannot attest the actual loaded source. Native must bind its existing loaded-configuration/held-child/Unix-peer proof to this bootId.

Prepare returns `{version:1,status:"prepared",bootId,kind,nonce,oldSHA256,newSHA256,bytes,sequence,previousGenerationSHA256,remainingMS}`. It reads only `CoreHome/RelayGeoInbox/<blobId>/<fixed basename>` using pinned directory FDs, NOFOLLOW, one-link regular files, exact owner/private modes and before/after identities. Fixed names: `GeoSite.dat`, `GeoIP.dat`, `Country.mmdb`, `ASN.mmdb`. Limit: 128 MiB each, 256 MiB for the sum of known Geo files after the selected replacement. Native also enforces its non-Geo static asset bytes plus all Geo files against the complete 256 MiB RuntimeAssets budget; Core cannot attest the non-Geo subtotal. The selected existing target and staged identity/content must match. Native owns bounded inbox publication; the renderer never supplies a path.

Applied returns `{version:1,status:"applied",bootId,kind,oldSHA256,newSHA256,bytes,sequence,previousGenerationSHA256,generationSHA256,retainedOriginal:true}`. Sequence must be the prepared value plus one. Generation is opaque to consumers; Core hashes a fixed domain-separated byte representation of bootId, sequence and all four kinds in the fixed enum order, using `absent` for missing rows. It never depends on platform JSON serialization.

Cancellation before publication admission consumes the nonce without changing files/head. After admission, errors, cancellation, lost response or unexpected identity yield `uncertain`, with no automatic retry, rollback or restart. A state read cannot silently clear uncertainty; reconciliation requires a fresh explicit transaction. Prepared/busy/stale/unsupported/cancelled/uncertain statuses contain no private paths/details. Admission publishes a new file by exclusive create and bounded synced writes, then swaps it with the fixed target, retaining the exact displaced old bytes. A successful receipt requires final target+retained-old identity/hash checks and the reader/cache generation publication. RENAME_SWAP is not expected-inode CAS against a hostile same-UID syscall adversary; anomalies remain uncertain and retain evidence.

## Reader/cache reuse and scope

DAT validation and matchers reuse the fixed standard loader and existing `ClearGeoSiteCache`/`ClearGeoIPCache`. Reset invalidates future lookups; already in-flight metadata/queries can complete against their captured old generation. Success does not promise an instantaneous switch for all previously admitted work.

MMDB/ASN reuse maxminddb-golang v1.12 `FromBytes`, metadata validation, verifier and existing Mihomo LookupCode/LookupASN. Controlled initialization is read-only and never removes/downloads missing or invalid assets. Whole DAT initialization reuses the fixed generated router protobuf types without forcing CN; selected rule/tag validation remains in the existing rule constructor. Initial and new controlled readers own immutable byte slices. Head publication is synchronized; old struct copies retain their immutable reader until Go GC. Published readers are never closed: this library's Close clears `buffer`, and the old updater's close-before-write is unsuitable for concurrent readers/failure preservation. No mmap, FD, bespoke decoder or refcount is added. Controlled mode is positively enabled only by the held launch environment `RELAY_LOCAL_GEODATA_V1=1`. Non-controlled startup keeps the fixed upstream initialization/reload paths. Existing network updater entry points (including Cron) are rejected in controlled mode even if a legacy geo-auto flag remains configured, so they cannot bypass the generation ledger or mutate a published reader. Requested App schedule intent and a live user grant are separate.

Native immutable owner and mutable geodata ledger are separate. Historical ResourceSnapshots/checked bundles stay immutable. A Core receipt alone does not authorize rewriting their old pins: Native must verify the exact held-owner target identities and advance its separate active ledger. Shipping variants/pins, extra/, source snapshots, user data and installed helper/Core/App are untouched until the coordinated pairing gate.

## Validation gates

First validate the other three kinds using existing fixed synthetic DAT and MaxMind test databases with equal-length data-only mutations, ordinary UID, a newly held private Core and the already calibrated exact-Unix plus one REJECT inbound deny-outbound sandbox. Concurrent MMDB/ASN lookups plus forced GC must not panic, read closed buffers, mix records or alter old copies; build/test use the verified private Go1.26.10/cache with GOPROXY=off and original go.mod/go.sum. Go race checks are private development tests, not real TUN/setuid/Intel acceptance. Large 128 MiB timing, alternate DAT loaders, failure/crash/readback and paired Native receipts must be evidenced separately; one small DAT result does not cover all variants.

## Exact publication registry

Core creates no directories. Its only new entry is `CoreHome/RelayGeo.retained-<nonce64hex>` for every kind. Before publication it is an exclusive candidate inode, fchowned to the pinned ordinary home UID/GID, checked0600/single-link, written and synced. A successful exchange leaves the exact original target inode/bytes at this exact name. Native may register it only after applied plus an independent match to the original identity/SHA. Never ignore/adopt/delete a prefix or a preexisting foreign entry.

Core never deletes, moves or mutates Inbox/UUID/staged entries. Prepare and cancellation before admission create nothing. After admission an error can leave the exact name containing candidate/partial bytes before exchange, or original bytes afterward; failed fchown can leave an empty inaccessible candidate. All remain uncertain and preserved. An EXCL collision leaves FOREIGN untouched and unowned. Neither nonce knowledge nor a filename proves ownership for cleanup; only the independent successful identity/content receipt does.

Controlled standard and memconservative DAT reads, including the latter's existing fallback, use fixed-name NOFOLLOW verified owned bytes. The existing standard protobuf decoder and memconservative emitBytes/decoder are reused. Valid non-controlled initialization/reader/reload/updater paths retain upstream behavior; malformed ASN/Meta records additionally return no match instead of unsafe slicing/type assertion panics.

Build with Node24 `node scripts/relay/build-core-geodata.mjs <fixed-source> <private-go-sdk-root> <private-cache-root> <fresh-/private/tmp/relay-geodata-integration-...>`; no download, shipping copy, pin generation or installation occurs. Source inventory and original module locks are verified before a readonly offline Darwin build (default ARM64, explicit `--arch=arm64|amd64`; AMD64 uses GOAMD64=v1 and is compile-only on this ARM host). The Go overlay is also emitted in that private output. `--verify-only` checks the fixed source set without compiling. Unknown or duplicate architecture/options are rejected; the output executable name includes the selected architecture. Run the targeted private units with the same three roots using `node --import ./node_modules/tsx/dist/loader.mjs scripts/relay/test-core-geodata-units.mjs ...`. Root-package parser tests replace only upstream main.go's eager CLI flag parser in a private test overlay; actual Core runs use the complete unchanged shipping main entry. The integration runner takes the new private binary, plus `--large` for an exact128MiB Country padding boundary or `--memconservative` for the two DAT loader cases. It calibrates each fresh sandbox before starting that one held child and verifies config bytes/inode, actual /configs, matching logs, retained bytes and child/TCP/Unix cleanup.

These development results do not include privileged/setuid/TUN execution, production Native/Core pipe coupling, current-user resource data, large complex real databases, power-loss/stress acceptance or all matcher/variant combinations. The128MiB fixture is a valid small MaxMind test database with an equal-length data mutation and unused padding; it proves byte-budget/I/O/deadline handling, not worst-case database parse complexity. Missing-kind first creation is intentionally unsupported in this first link and remains a separate explicit expected-absence transaction, not an instruction to stop/restart Core. Native must retain immutable bundle pins and advance only its verified mutable active ledger.
