# Explicit Relay scoped CLI source contract

This is an additional limited launch capability within G05 / batch 44. It does not complete the original all-CLI/tool coverage requirement of batch 42. It runs a publisher-approved pinned Node 24.5+ (24.x) and fixed CLI JS resource with one noninteractive `-p` prompt. Existing projects are read-only; generated files can only be written in the new session's private work/HOME. It does not edit the user's original Claude settings/HOME, select an arbitrary executable or use Electron run-as-node. API key is memory/environment input, never a Relay configuration/log; bounded output stays only in Main/UI memory, with exact-key streaming redaction. This is not an interactive editable Claude Code replacement.

Current publication authority is false and CLI resources are false/null, so no launch is available. The offline resource preparer accepts only explicitly approved distributable paired bytes for both architectures, thin Mach-O CPU/hash pins, exact provenance and license files; it never downloads, installs, invokes, signs or upgrades a CLI. Production App resource sealing and fixed signed Main host verification are prerequisites. The offline preparer output can be staged as extra/relay/guard-cli for the existing Relay resource mapping; fixed Node signIgnore rows preserve approved bytes, and the afterSign hook rechecks both architectures, exact reviewed definition, SHA/Mach-O type, provenance and licenses without executing a bundled program. Absent/default-off resources remain unavailable. Changing a renderer Boolean, path, command, PID or manifest in mutable state cannot authorize launch.

The Main-only native scoped proof authenticates the compiled publisher and actual signed own Main/App resource envelope, exact bundled owned Core PID/birth/listener identity and captured config SHA. It does not query, install or enable a system filter and is independent of full-scope NE readiness. A separate immutable proof is checked before/after each new tunnel/request and by a coalesced 500ms lease watch. Guard status/approval cannot overwrite or stall this local proof. Core mutation and Main quit honor the scoped activity barrier.

A minimal macOS Seatbelt profile is adapted from Anthropic sandbox-runtime commit 27fce0dbd58925061c57eb8b38707b9a98349dad (0.0.81). All remote sockets/UDP/DNS/other loopback/Unix/Mach/AppleEvent delegation and writes outside private HOME/work are denied by default. The narrower remote tcp filter is also present in installed Apple sandbox profile source (for example com.apple.GameOverlayUIInternal.sb); its source bytes are recorded, no profile was executed. The only outbound socket destination is the Main-owned 127.0.0.1 HTTPS proxy port. Inherited descriptors are only the new child's stdio pipes; the pinned Node 24.5 libuv spawn source uses POSIX_SPAWN_CLOEXEC_DEFAULT and a new process group. Ordinary fork/exec descendants retain the profile. No global Node/CLI or unrelated process configuration changes.

The HTTPS proxy adapts SRT parent-proxy CONNECT parsing. Its session CA and leaf are generated by cached PKIjs 3.4.1 and pinned transitive code; crypto algorithms are supplied by Node WebCrypto. Keys stay in Main memory, never in a file. The public CA is in read-only support outside writable sandbox roots. Authenticated CONNECT/HTTP forwarding dials only the captured dedicated Core port 17891, never target DNS/direct. Target TLS is opaque. Node `--use-env-proxy` plus NODE_EXTRA_CA_CERTS, curl's separate `proxy-cacert` in isolated CURL_HOME, Git http.proxySSLCAInfo/GIT_PROXY_SSL_CAINFO, and npm's mature HTTPS-proxy agents keep proxy trust separate from origin trust; TLS verification is never disabled. Tools ignoring proxy settings fail closed at the remote network boundary.

Main loss closes all TLS connections; a normal TLS-validating descendant cannot accept a re-bound port without the private session key. Explicit stop confirms and signals only the newly spawned live process group; leader/drain uncertainty retains the window, with no force kill, foreign PID adoption, broad shutdown or automatic fallback. Pending launch intent is generation-revoked on cancel/navigation/close; late approvals cannot spawn. Broker/lease loss closes sockets and local proof. These are source-level mechanisms, not observed OS behavior yet.

Threat model is ordinary explicitly launched tools with TLS validation, avoiding accidental remote leaks. It excludes malicious local collusion, deliberate TLS-disable/raw-socket clients, reading Main memory, external arbitrary Node/CLI sessions not launched through Relay, and delegated network behavior that bypasses this constrained launch. Mature EndpointSecurity/BlockBlock sources were read: AUTH_EXEC plus responsible-audit-token/script hints do not safely establish generic interpreter/descendant origin for every external process without a larger trusted launch/ES protocol and entitlement. They were not integrated as false global coverage. completeClientScopeReady and protectionVerified remain false. No live filter or global unknown-identity-drop policy is deployed.

Fixed source reuse records: Electron v43.8.0 Swift addon sample; Apple FilteringNetworkTraffic zip SHA256 73bdbda7edfc6ecc74e39cfbf4a44833c40096884f688683252fc6160c1514e9; SRT above; Node v24.5.0 env-proxy docs/internal undici/libuv spawn; Git v2.51.1 http.adoc/http.c; curl curl-8_17_0 tool_getparam; npm cli v11.5.2 + make-fetch-happen14.0.3 + @npmcli/agent3.0.0 and cached proxy agents. Local upstream source bytes and hashes are kept in the private job. Vendor provenance records exact cached package input hashes, versions, licenses and source-only esbuild/prettier output. No package.json or lockfile changes/install.

Remaining original scope: independently launched arbitrary Node/CLI and malicious/custom TLS cases are not covered by this launch. Full desktop/system-filter behavior, existing flow handling, OS delegated traffic, UDP/IPv6 faults, CLI/tool compatibility, process drain and failure recovery require the user's deferred unified validation and explicit system-operation authorization. A compiled default-off release flag or a passing static check is never a protected status or acceptance result.

The scoped CLI writable HOME/work and read-only proxy support now use the fixed Main-owned sibling Library/Application Support/Relay-ScopedCLI/Sessions/<Main-generated UUID>, outside Relay-Preview and Maintenance/Bootstrap. Existing SubscriptionFiles context rules are unchanged; a dedicated helper creates an exclusive 0700 session, verifies ancestors and bound directory identities, and writes only 0600 non-secret retention metadata plus the public CA/curl support files. No user path or arbitrary write API is exposed. Native approval and per-launch validity are still required before creation; identity is repeated before spawn. Existing Root/ScopedCLI content is not moved or deleted and remains blocked by the conservative C05 gate.

This removes the new CLI workspace's write coupling to the fixed Relay-Preview root rename. It does not prove all descendants exited, implement automatic cleanup/archive, or include the retained CLI area in the separate Relay-Preview whole-root reset. The UI and concrete launch confirmation disclose that files are retained independently and that parent exit is not full-tree closure. No process is adopted/stopped to clean these directories and no runtime gate or original all-CLI scope is widened.
